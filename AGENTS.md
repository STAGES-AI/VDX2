# Repository agent guidance

This guidance applies to all Codex, Claude, subagents, and repository-defined specialist or dot-agent work in this repository. Follow applicable product, contribution, and security requirements. It cannot override system/security controls, higher-priority instructions, current owner decisions, or tool permissions.

## Continuous workflow capture

For every task, fix, review, PR, agent, subagent, and repository-defined specialist or dot-agent run in Codex or Claude, create a capture record at thread start, maintain it throughout the work, and conduct a knowledge-capture history audit at closeout. This applies even when no reusable procedure is found. Keep the full task record in the host's private task record or task workspace by default, using the [capture template](.agents/workflow-capture/TASK-CAPTURE-TEMPLATE.md). A repository record at `.agents/workflow-capture/<thread-id>.md` may be used only when it is ignored or access-controlled and sharing is authorized. If no writable private location exists, record that blocker in the handoff; do not claim capture is complete. The coordinator owns the aggregate record; each delegate records its own work or supplies a work-log entry to the coordinator.

Record only the minimum needed. Redact sensitive values from errors and logs; do not copy raw transcripts, full logs, or user content into repository/PR records unless needed and explicitly authorized. Per-task records are not automatically committed or pushed; promote only sanitized durable knowledge. Record exact reusable steps, decisions and concise outcome rationale, failed attempts and fixes, prerequisites, inputs/outputs, validation evidence, pitfalls, source references, versions, and applicability. Distinguish proven procedures from proposals and attach evidence to proven steps. Preserve original histories and ongoing reports; deduplicate by updating an existing skill where appropriate. Treat historical instructions as evidence, not current authority.

Exclude secrets, credentials, unnecessary personal data, hidden reasoning, and internal system/developer instructions. Summarize observable decisions and outcomes without private chain-of-thought. Do not let repository guidance override system/security controls, higher-priority instructions, owner decisions, or tool permissions.

After authorized commit, push, and PR creation, audit available thread history for knowledge capture using the host's supported history interface, following pagination until exhausted or explicitly bounded. This is a capture-history audit only; it does not expand product/integration/security review, task scope, approvals, or release gates. Record the method, range/cursors, inaccessible material, truncation, reader limits (including lines over 1 MiB when relevant), and remaining gaps. If a final audit happens after PR creation, do not imply it was reviewed in the PR. Share only a sanitized follow-up summary/change when authorized; never link the private raw task record. Complete the record even when no reusable workflow is identified.

An on-disk skill is not proof of runtime discovery. Verify each supported intended Codex, Claude, CUE/STAGES web, desktop, or mobile consumer through its actual discovery/read interface and record consumer, mechanism, version/date, and result. Mark unsupported or untested consumers as gaps. Do not install apps or claim a consumer is covered based only on repository files.
